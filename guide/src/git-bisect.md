# การไบเซกต์ด้วย Git สำหรับบิลด์ที่กำหนดเอง

มีบางกรณีที่พบได้ยากที่คุณอาจต้องบิลด์ `rustc` ด้วยตัวเลือกที่กำหนดเอง หรือต้องหลีกเลี่ยงปัญหาเกี่ยวกับคอมไพเลอร์สำเร็จรูปที่ไม่มีให้ใช้
สำหรับกรณีนี้คุณสามารถใช้ [`git bisect`] เพื่อบิลด์คอมไพเลอร์ในเครื่องของคุณเองได้

การใช้อาร์กิวเมนต์ `--first-parent` อาจมีประโยชน์ เพื่อให้ไบเซกต์เฉพาะคอมมิต merge ที่เข้าถึงได้โดยตรงบน default branch
มิฉะนั้นการไบเซกต์อาจไปลงที่คอมมิตกลางภายใน PR ซึ่งอาจบิลด์หรือทดสอบไม่ผ่าน

ในการเริ่มการไบเซกต์ ให้ระบุขอบเขตที่จะเริ่มไบเซกต์:

```sh
git bisect start --first-parent
git bisect good 96ddd32c4bfb1d78f0cd03eb068b1710a8cebeef
git bisect bad a00f8ba7fcac1b27341679c51bf5a3271fa82df3
```

จากนั้น บิลด์คอมไพเลอร์ตามที่จำเป็นและรันการทดสอบของคุณเพื่อตรวจหารีเกรสชัน:

```sh
./x.py build std
rustc +stage1 foo.rs
```

คุณอาจควรพิจารณารัน `./x.py clean` ถ้าคุณเจอปัญหา เนื่องจากการเปลี่ยนแปลงโครงสร้างภายในของอาร์ติแฟกต์การบิลด์ไม่ได้ถูกควบคุมเวอร์ชันเสมอไป และการเปลี่ยนแปลงเหล่านั้นอาจเข้ากันไม่ได้
แคชอินครีเมนทัล (incremental caches) อ่อนไหวเป็นพิเศษ ดังนั้นคุณอาจต้องการปิดมันถ้าคุณเปิดไว้

ถ้าคุณตัดสินใจว่าเวอร์ชันปัจจุบันดีหรือแย่ ให้รัน `git bisect good` หรือ `git bisect bad` เพื่อทำเครื่องหมาย จากนั้นทำการบิลด์และทำเครื่องหมายซ้ำจนกว่าเสร็จ

คล้ายกับ `cargo-bisect-rustc` ตรงที่ `git bisect` รองรับการเขียนสคริปต์และลูกเล่นอื่น ๆ อีกมากมาย
ดูเอกสารประกอบของมันสำหรับรายละเอียดเพิ่มเติม

[`git bisect`]: https://git-scm.com/docs/git-bisect
