# การไบเซกต์ด้วย Git สำหรับบิลด์ที่กำหนดเอง

ในบางกรณีที่พบได้ไม่บ่อยนัก คุณอาจจำเป็นต้องบิลด์ `rustc` ด้วยตัวเลือกที่กำหนดขึ้นเอง (custom options) หรือต้องแก้ปัญหาเฉพาะหน้าเมื่อไม่มีคอมไพเลอร์แบบสำเร็จรูป (pre-built) ให้ดาวน์โหลดใช้งาน
สำหรับกรณีนี้ คุณสามารถใช้ [`git bisect`] เพื่อช่วยควบคุมการบิลด์คอมไพเลอร์ในเครื่องของคุณเองได้

การระบุตัวเลือก `--first-parent` จะมีประโยชน์อย่างยิ่ง เพราะจะช่วยจำกัดการไบเซกต์ให้ตรวจเฉพาะคอมมิตการ merge ที่อยู่บน default branch โดยตรง
มิฉะนั้นการไบเซกต์อาจสุ่มไปเจอกลางคอมมิตย่อย (intermediate commits) ภายใน PR ซึ่งอาจยังบิลด์ไม่ผ่านหรือทดสอบไม่สมบูรณ์

ในการเริ่มต้นไบเซกต์ ให้ระบุขอบเขตจุดเริ่มต้นและสิ้นสุดที่จะทำการไบเซกต์:

```sh
git bisect start --first-parent
git bisect good 96ddd32c4bfb1d78f0cd03eb068b1710a8cebeef
git bisect bad a00f8ba7fcac1b27341679c51bf5a3271fa82df3
```

จากนั้น บิลด์คอมไพเลอร์ตามที่จำเป็นและสั่งรันการทดสอบของคุณเพื่อตรวจหารีเกรสชัน:

```sh
./x.py build std
rustc +stage1 foo.rs
```

หากคุณพบปัญหาแปลกๆ ระหว่างบิลด์ อาจลองพิจารณาสั่งรัน `./x.py clean` ดู เนื่องจากโครงสร้างภายในของอาร์ติแฟกต์การบิลด์อาจไม่มีการกำหนดเวอร์ชันควบคุมไว้ทั้งหมด และความเปลี่ยนแปลงระหว่างคอมมิตอาจเข้ากันไม่ได้
โดยเฉพาะอย่างยิ่ง แคชการคอมไพล์แบบอินครีเมนทัล (incremental caches) มักจะเกิดปัญหาได้ง่าย หากคุณเปิดใช้งานไว้จึงแนะนำให้ปิดก่อน

เมื่อทดสอบและระบุได้แล้วว่าเวอร์ชันปัจจุบันทำงานถูกต้อง (good) หรือมีปัญหา (bad) ให้สั่ง `git bisect good` หรือ `git bisect bad` เพื่อมาร์กผลลัพธ์ แล้วทำซ้ำขั้นตอนการบิลด์และมาร์กนี้ไปเรื่อยๆ จนกว่าจะเสร็จสิ้นกระบวนการ

เช่นเดียวกับ `cargo-bisect-rustc` คำสั่ง `git bisect` รองรับการเขียนสคริปต์อัตโนมัติและมีลูกเล่นอื่นๆ ให้ใช้งานอีกมากมาย
สามารถศึกษาเพิ่มเติมได้จากเอกสารทางการของ git

[`git bisect`]: https://git-scm.com/docs/git-bisect
