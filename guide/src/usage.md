# การใช้งานพื้นฐาน

การใช้ `cargo-bisect-rustc` ง่าย ๆ คือการรันมันภายในโปรเจกต์ Cargo ที่จำลองรีเกรสชันได้:

```sh
cargo bisect-rustc
```

> สำหรับการเริ่มต้นอย่างรวดเร็ว ดูที่บท [บทช่วยสอน](tutorial.md)

`cargo-bisect-rustc` ทำงานโดยการบิลด์โปรเจกต์ Cargo และตรวจจับว่าการบิลด์สำเร็จหรือล้มเหลว
เครื่องมือจะดาวน์โหลดและใช้ทูลเชน nightly ของ Rust
โดยเริ่มจากขอบเขต nightly สองจุด เรียกว่า *start* ซึ่งโปรเจกต์บิลด์ผ่าน (หรือ *baseline*) และ *end* ซึ่งรู้ว่าล้มเหลว (หรือ *regression*)
จากนั้นเครื่องมือจะทำการค้นหาแบบไบนารีระหว่างวันที่ทั้งสอง เพื่อหา nightly ที่โปรเจกต์เริ่มล้มเหลว

เมื่อพบ nightly ที่เริ่มล้มเหลว `cargo-bisect-rustc` จะพยายามหา PR แต่ละตัวที่ทำให้เกิดรีเกรสชัน
โปรเจกต์ Rust เก็บบิลด์ของ PR ที่ถูก merge ทุกตัวในช่วง 167 วันล่าสุด
ถ้า nightly อยู่ในช่วงดังกล่าว เครื่องมือจะไบเซกต์ระหว่าง PR เหล่านั้น

และไปได้ไกลกว่านั้นอีก ถ้ารีเกรสชันอยู่ใน [โรลอัป PR] เครื่องมือจะไบเซกต์ PR แต่ละตัวภายในโรลอัปนั้น
การไบเซกต์ขั้นสุดท้ายนี้ใช้ได้เฉพาะ `x86_64-unknown-linux-gnu` เพราะใช้บิลด์ที่สร้างสำหรับ [ตัวติดตามประสิทธิภาพของ rustc]

[โรลอัป PR]: https://forge.rust-lang.org/release/rollups.html
[ตัวติดตามประสิทธิภาพของ rustc]: https://perf.rust-lang.org/

`cargo-bisect-rustc` จำเป็นต้องอ่าน git log ของรีโพสิทอรี [`rust-lang/rust`] เพื่อสแกนคอมมิตแต่ละตัว

## ขอบเขต (Boundaries)

หากไม่ตั้งค่าตัวเลือกใด ๆ `cargo-bisect-rustc` จะพยายามหา *start* ที่บิลด์ผ่านและ *end* ที่ล้มเหลวโดยอัตโนมัติ
วิธีนี้อาจใช้เวลาพอสมควร ขึ้นอยู่กับว่าต้องสแกนย้อนหลังไปไกลแค่ไหน
แนะนำให้ใช้ตัวเลือก `--start` และ `--end` เพื่อระบุตำแหน่งขอบเขต

```sh
cargo bisect-rustc --start=2022-11-01 --end=2023-02-14
```

ดูบท [ขอบเขตการไบเซกต์] สำหรับรายละเอียดเพิ่มเติมเกี่ยวกับการตั้งค่าตัวเลือกเหล่านี้

[ขอบเขตการไบเซกต์]: boundaries.md

## การตรวจสอบรีเกรสชัน

โดยค่าเริ่มต้น `cargo-bisect-rustc` ถือว่า *start* บิลด์ผ่าน และ *end* บิลด์ล้มเหลว
คุณเปลี่ยนได้โดยใช้ตัวเลือก `--regress`
ตัวอย่างเช่น คุณสามารถบอกได้ว่า *start* ควรล้มเหลว และ *end* ควรผ่าน
มีตัวเลือกหลายอย่างที่ใช้ร่วมกับ `--regress`:

<style>
    table td:nth-child(1) {
        white-space: nowrap;
    }
</style>

| ตัวเลือก | Start | End | คำอธิบาย |
|--------|-------|-----|-------------|
| `error` | ผ่าน | ล้มเหลว | การตั้งค่าเริ่มต้น ตรวจสอบว่าความล้มเหลวคือรีเกรสชัน |
| `success` | ล้มเหลว | ผ่าน | กลับด้านการตรวจสอบเพื่อหาจุดที่บางอย่าง *ถูกแก้ไข* |
| `ice` | ไม่มี ICE | ICE | สแกนหาจุดที่เกิด Internal Compiler Error (ICE) |
| `non-ice` | ICE | ไม่มี ICE | สแกนหาจุดที่ ICE ถูกแก้ไข |
| `non-error` | ล้มเหลวแบบไม่ใช่ ICE | ผ่านหรือ ICE | สแกนหาจุดที่โปรแกรมที่ไม่ถูกต้องหยุดถูกปฏิเสธอย่างถูกต้อง หรือคอมไพเลอร์เริ่มเกิด ICE |

ดูหัวข้อ [การเขียนสคริปต์](#การเขียนสคริปต) สำหรับการปรับแต่งพฤติกรรมนี้

## คำสั่งที่กำหนดเอง

โดยค่าเริ่มต้น `cargo-bisect-rustc` รัน `cargo build`
คุณเปลี่ยนคำสั่ง cargo ที่จะรันได้โดยส่งอาร์กิวเมนต์เพิ่มเติมหลัง `--`:

```sh
cargo bisect-rustc -- test --test mytest
```

## การเขียนสคริปต์

คุณสามารถใช้สคริปต์ตามอำเภอใจเพื่อกำหนดว่าอะไรคือ baseline และอะไรคือรีเกรสชัน
นี่เป็นตัวเลือกที่ยืดหยุ่นมาก ซึ่งทำให้คุณสามารถทำงานใด ๆ ได้โดยอัตโนมัติ
เพียงส่ง path ไปยังสคริปต์ให้กับตัวเลือก `--script`:

```sh
cargo bisect-rustc --script ./test.sh
```

สคริปต์ควรคืนค่า exit code 0 สำหรับ baseline และคืนค่าไม่ใช่ 0 สำหรับรีเกรสชัน
เนื่องจาก `cargo-bisect-rustc` ตั้งค่า `RUSTUP_TOOLCHAIN` (ดู [ทูลเชนของ Rustup](rustup.md)) สิ่งที่คุณต้องทำคือเรียกใช้ `cargo` หรือ `rustc` แล้วสคริปต์จะใช้ทูลเชนที่กำลังทดสอบอยู่โดยอัตโนมัติ

```sh
#!/bin/sh

set -ex

# This checks that a warning is only printed once.
# See https://github.com/rust-lang/rust/issues/88256 for a regression where it
# started printing twice.

OUTPUT=`cargo check 2>&1`
COUNT=`echo "$OUTPUT" | grep -c "unnecessary parentheses"`
test $COUNT -eq 1
```

หากคุณต้องการใช้ targets โดยตรงโดยไม่ใช้ `cargo` ในสคริปต์ ไฟล์บิลด์จะอยู่ใน `$CARGO_TARGET_DIR/[release|debug]/...` เนื่องจาก `cargo-bisect-rustc` ตั้งค่า `$CARGO_TARGET_DIR` ให้
