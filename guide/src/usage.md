# การใช้งานพื้นฐาน

วิธีใช้งาน `cargo-bisect-rustc` ง่ายๆ คือสั่งรันคำสั่งนี้ภายในโปรเจกต์ Cargo ที่ทำให้เกิดปัญหา (reproduce รีเกรสชันได้):

```sh
cargo bisect-rustc
```

> สำหรับการเริ่มต้นใช้งานอย่างรวดเร็ว สามารถดูได้ที่บท [บทช่วยสอน](tutorial.md)

หลักการทำงานของ `cargo-bisect-rustc` คือจะบิลด์โปรเจกต์ Cargo แล้วตรวจดูว่าการบิลด์สำเร็จหรือล้มเหลว
โดยเครื่องมือจะดาวน์โหลดและเรียกใช้ทูลเชน nightly ของ Rust
เริ่มต้นจากขอบเขต nightly สองจุด ได้แก่ *start* ซึ่งเป็นจุดที่โปรเจกต์บิลด์ผ่าน (เรียกว่า *baseline*) และ *end* ซึ่งเป็นจุดที่ทราบว่าบิลด์ล้มเหลว (เรียกว่า *regression*)
จากนั้นเครื่องมือจะค้นหาแบบไบนารี (binary search) ระหว่างวันที่ทั้งสอง เพื่อหาว่าเวอร์ชัน nightly ใดที่โปรเจกต์เริ่มบิลด์ล้มเหลว

เมื่อพบเวอร์ชัน nightly ที่เริ่มเกิดปัญหาแล้ว `cargo-bisect-rustc` จะพยายามค้นหาต่อไปว่า PR ใดเป็นต้นเหตุที่ทำให้เกิดรีเกรสชัน
โดยปกติโปรเจกต์ Rust จะเก็บบิลด์ของทุก PR ที่ถูก merge ไว้เป็นเวลาย้อนหลัง 167 วัน
หาก nightly ที่พบอยู่ในช่วงเวลาดังกล่าว เครื่องมือจะทำการไบเซกต์ย่อยระหว่าง PR เหล่านั้นให้โดยอัตโนมัติ

ยิ่งไปกว่านั้น หากพบว่ารีเกรสชันแฝงอยู่ใน [โรลอัป PR] เครื่องมือยังสามารถไบเซกต์แยกตามแต่ละ PR ย่อยที่รวมอยู่ในโรลอัปนั้นได้อีกด้วย
(ทั้งนี้ การไบเซกต์ขั้นสุดท้ายนี้รองรับเฉพาะบน `x86_64-unknown-linux-gnu` เนื่องจากต้องอาศัยบิลด์ที่สร้างไว้สำหรับ [ตัวติดตามประสิทธิภาพของ rustc])

[โรลอัป PR]: https://forge.rust-lang.org/release/rollups.html
[ตัวติดตามประสิทธิภาพของ rustc]: https://perf.rust-lang.org/

## รีโพสิทอรีซอร์สโค้ดของ Rust

`cargo-bisect-rustc` จำเป็นต้องอ่าน git log ของรีโพสิทอรี [`rust-lang/rust`] เพื่อใช้ไล่ดูคอมมิตแต่ละตัว
สามารถดูวิธีตั้งค่าการเข้าถึงรีโพสิทอรี git ได้ในบท [ซอร์สโค้ดของ Rust]

[ซอร์สโค้ดของ Rust]: rust-src-repo.md
[`rust-lang/rust`]: https://github.com/rust-lang/rust/

## ขอบเขต (Boundaries)

หากไม่ได้ระบุตัวเลือกใดๆ `cargo-bisect-rustc` จะพยายามค้นหาจุด *start* ที่บิลด์ผ่าน และจุด *end* ที่บิลด์ล้มเหลวให้โดยอัตโนมัติ
ซึ่งอาจใช้เวลาพอสมควรขึ้นอยู่กับว่าต้องสแกนย้อนหลังไปไกลเพียงใด
ดังนั้น จึงแนะนำให้ใช้ตัวเลือก `--start` และ `--end` เพื่อระบุขอบเขตวันที่ที่ต้องการ

```sh
cargo bisect-rustc --start=2022-11-01 --end=2023-02-14
```

ดูรายละเอียดเพิ่มเติมเกี่ยวกับการตั้งค่าตัวเลือกเหล่านี้ได้ที่บท [ขอบเขตการไบเซกต์]

[ขอบเขตการไบเซกต์]: boundaries.md

## การตรวจสอบรีเกรสชัน

โดยค่าเริ่มต้น `cargo-bisect-rustc` จะถือว่าขอบเขต *start* ต้องบิลด์ผ่าน และขอบเขต *end* ต้องบิลด์ล้มเหลว
คุณสามารถเปลี่ยนเกณฑ์นี้ได้โดยใช้ตัวเลือก `--regress`
ตัวอย่างเช่น คุณสามารถกำหนดให้ *start* ล้มเหลว และ *end* บิลด์ผ่าน
โดยมีตัวเลือกต่างๆ ที่สามารถใช้ร่วมกับแฟล็ก `--regress` ดังนี้:

<style>
    table td:nth-child(1) {
        white-space: nowrap;
    }
</style>

| ตัวเลือก | Start | End | คำอธิบาย |
|--------|-------|-----|-------------|
| `error` | ผ่าน | ล้มเหลว | ค่าเริ่มต้น ใช้ตรวจสอบว่าการบิลด์ล้มเหลวคือรีเกรสชัน |
| `success` | ล้มเหลว | ผ่าน | กลับด้านการตรวจสอบ เพื่อหาจุดที่ปัญหา *ได้รับการแก้ไข* |
| `ice` | ไม่มี ICE | ICE | สแกนหาจุดที่เริ่มเกิด Internal Compiler Error (ICE) |
| `non-ice` | ICE | ไม่มี ICE | สแกนหาจุดที่ ICE ได้รับการแก้ไข |
| `non-error` | ล้มเหลวแบบไม่ใช่ ICE | ผ่านหรือ ICE | สแกนหาจุดที่โค้ดผิดรูปแบบ (ill-formed) หยุดถูกปฏิเสธ (ยอมให้ผ่าน) หรือคอมไพเลอร์เริ่มเกิด ICE |

ดูหัวข้อ [การเขียนสคริปต์](#การเขียนสคริปต) สำหรับการปรับแต่งพฤติกรรมนี้

## คำสั่งที่กำหนดเอง

โดยค่าเริ่มต้น `cargo-bisect-rustc` จะรันคำสั่ง `cargo build`
คุณสามารถเปลี่ยนคำสั่ง `cargo` ที่ต้องการรันได้โดยส่งอาร์กิวเมนต์เพิ่มเติมต่อท้ายหลังเครื่องหมาย `--`:

```sh
cargo bisect-rustc -- test --test mytest
```

## การเขียนสคริปต์

คุณสามารถใช้สคริปต์ใดๆ ที่กำหนดขึ้นเองเพื่อระบุว่าเงื่อนไขใดคือ baseline และเงื่อนไขใดคือรีเกรสชัน
นี่เป็นตัวเลือกที่ยืดหยุ่นอย่างยิ่ง ซึ่งเปิดโอกาสให้คุณกำหนดการทำงานอัตโนมัติได้อย่างอิสระ
เพียงส่ง path ของสคริปต์ให้กับตัวเลือก `--script`:

```sh
cargo bisect-rustc --script ./test.sh
```

สคริปต์ควรกำหนดให้ exit code เป็น 0 สำหรับสถานะ baseline และ exit code ไม่เท่ากับ 0 สำหรับสถานะรีเกรสชัน
เนื่องจาก `cargo-bisect-rustc` จะเป็นผู้กำหนดตัวแปรสภาพแวดล้อม `RUSTUP_TOOLCHAIN` ให้โดยอัตโนมัติ (ดู [ทูลเชนของ Rustup](rustup.md)) ภายในสคริปต์คุณจึงเพียงแค่เรียกใช้คำสั่ง `cargo` หรือ `rustc` ตามปกติ แล้วคำสั่งจะเลือกใช้ทูลเชนที่กำลังทดสอบอยู่ทันที

```sh
#!/bin/sh

set -ex

# This checks that a warning is only printed once.
# See https://github.com/rust-lang/rust/issues/88256 for a regression where it
# started printing twice.

OUTPUT=`cargo check 2>&1`
COUNT=`echo "$OUTPUT" | grep -c "unnecessary parentheses"`
test $COUNT -eq 1
```

หากในสคริปต์คุณจำเป็นต้องเข้าถึงไฟล์ไบนารีผลลัพธ์ (build targets) โดยตรงโดยไม่ผ่าน `cargo` ไฟล์ที่บิลด์แล้วจะอยู่ใน `$CARGO_TARGET_DIR/[release|debug]/...` เนื่องจาก `cargo-bisect-rustc` จะเป็นผู้กำหนดค่าตัวแปร `$CARGO_TARGET_DIR` ให้

สามารถดูตัวอย่างการประยุกต์ใช้งานตัวเลือกนี้ในหลากหลายสถานการณ์ได้ที่บท [ตัวอย่าง](examples/index.md)
